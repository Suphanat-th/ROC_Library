# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout
- `roc-library/` — the active app: Next.js 16 (App Router) utility site for Ragnarok Online Classic (ROC). All work happens here.
- `AGENTS.md` — overlapping agent instructions; keep in sync with this file.

## Commands (run inside `roc-library/`)
```bash
npm run dev     # dotenv -e environment/.env.local -- next dev --webpack (env file must exist)
npm run build   # next build --webpack
npm run lint    # eslint
```
There is no test framework and no separate typecheck script; `npm run build` is the way to catch type errors. Do not add test commands without adding dependencies.

## Stack notes
- React is **18** (`react@^18.2.0`) despite AGENTS.md saying 19.
- React Compiler is enabled (`reactCompiler: true` in `next.config.ts`) — avoid manual `useMemo`/`useCallback` unless needed.
- Tailwind v4 + DaisyUI 5. Custom themes `roc-light` (default) / `roc-dark` defined in `src/app/globals.css`; toggled by `ThemeToggle` and saved in `localStorage` (`roc-theme`). Use theme tokens (`bg-base-*`, `text-base-content`, `text-primary`) rather than raw `gray-*`/`blue-*` for surfaces and text so dark mode works. Font: local Mali via `next/font/local`.
- Path alias `@/*` → `src/*`.
- Other libs: leaflet/react-leaflet (dungeon maps), swiper, framer-motion, html-to-image (image export), lucide-react.

## Architecture
- **Shell**: `src/app/layout.tsx` wraps everything in `LoadingProvider` (`src/context/LoadingContext.tsx`, global `useLoading()` overlay) and a custom `.shell` (not DaisyUI's drawer; CSS in `globals.css`): `src/layout/navbar` is the full-width top bar, and `src/layout/sidebar` is a full-screen hi-tech menu (tiles grouped by folder, search box) opened by the hidden checkbox `#sidebar-flip` (checked = open, CSS-only; Esc, the close button and choosing a Tool uncheck it). Sidebar effects deliberately ignore `prefers-reduced-motion`. Adding a new tool page means creating `src/app/<route>/page.tsx` and adding a link in `sidebar.tsx`.
- **Routes** in `src/app/` are independent tools (calculators like `aspd-calc`, `exp-calc`, `cast-calc`, `calc-bp`; guides like `facewormnest-guide`, `toyfactory-guide`, `endless-tower`; `patch-convert`, `visual` (sprite viewer), `vip-search`, etc.). Page-specific components live in a colocated `components/` folder; shared ones in `src/components/`.
- **Data comes from three places**:
  1. `public/assets/json/*.json` fetched client-side by hook-style services (e.g. `useItemDb()` in `src/services/patchData/itemsService.tsx`).
  2. Hardcoded TS tables in `src/data/` (exp tables, ASPD, battle pass, enchant stones, research) and `src/services/mapData`, `src/services/mosters` (sic).
  3. `src/app/api/vip/route.ts` — the only API route; paginated/search over `src/data/vipDatabase.json` via `src/services/vip/vipService.ts`.
- **Hand-maintained event config**: `src/services/serverInfo/*` (exp/drop/death rate events with `DateFrom`/`DateTo`) and `src/config/maintenanceWindow.ts` are edited by hand as server events change. JS `Date` months are 0-indexed; times are Thailand (GMT+7) — use `src/utils/timezoneUtils.ts`.
- **Dev-only tools**: `/random-scroll/facebook` is the Comment draw (see GLOSSARY): `src/app/api/dev/comment-draw` fetches one Facebook Page post's comments (Graph API, `FB_PAGE_ACCESS_TOKEN` / optional `FB_PAGE_ID` in `environment/.env.local`), takes pasted comment text for Facebook names (the API hides commenters), and saves reviews and Winners in gitignored `roc-library/dev-data/comment-draw/`. Rules live in `src/utils/commentDraw.ts`; storage in `src/data/commentDraw.ts`, gated by `devToolsEnabled` (404 / hidden when `NODE_ENV === "production"`).
- **Domain logic** in `src/utils/`: binary SPR/ACT sprite parsers (`sprParser.ts`, `actParser.ts`), `aspdFormula.ts`, `researchCalc.ts`.
- **MVP Hunter** (`/mvp`, see GLOSSARY): MVPs and Mini bosses are the monsters in `src/services/mosters/mostersDb.tsx` that carry `mapspawn` (`miniBoss: true` marks a Mini boss; Spawn map + `cooldown` in minutes, hand-kept from RateMyServer's Renewal DB, `[0, 0]` for a Mini boss that returns within seconds; optional `routeNote` / `routeVia` where the game's Warp list stops short). Routes are worked out in the browser (`src/utils/mapRoute.ts`: fewest Warps, then least Zeny) from `public/assets/json/MapLinks.json`; that file and `public/assets/images/minimap/*.webp` are generated from the game client by `node scripts/extract-navigation.mjs "<path to data.grf>"` (towns, blocked maps, missing map names and the Gate Warp — the server's own NPC, which the client's Warp list lacks — are constants at its top; rerun after a patch or after adding a Spawn map). Death times (full date and time) live in `localStorage` (`roc-mvp-death-times`); time maths in `src/utils/mvpRespawn.ts`. "แจ้งข้อมูลผิด" posts a Spawn report to `src/app/api/boss-report/route.ts`, which saves it to the Supabase table `boss_reports` (create it with `supabase/boss_reports.sql`; needs `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`). The dev-only Report board at `/dev/mvp-reports` and Feedback board at `/dev/feedback` (`src/app/dev/*`, APIs `src/app/api/dev/{mvp-reports,feedback}`) list the Supabase rows ten a page and tick them (`fixed_at` on `boss_reports`, `read_at` on `feedback`; create the columns with `supabase/boss_reports.sql` / `supabase/feedback.sql`). Both share `src/components/dev/NoteBoard.tsx` and `src/utils/devBoard*.ts`; gating is the Comment draw's `devToolsEnabled` plus a localhost-only host check.
- **Costume simulator** (`/costume`, see GLOSSARY, ADR 0004): Members-only page (`CostumeGate`) that draws a character in the browser from the game's own sprites. `node scripts/extract-costume.mjs` reads `data.grf` and `System/iteminfo_new.lub` (readers in `scripts/lib/`) and writes `public/assets/json/CostumeIndex.json` (committed), `public/assets/images/costume/icons.png` (committed) and the sprite packs in `public/assets/costume/` (gitignored: bodies, heads, headgear `hg/`, Robes `rb/` as RCP1 packs with an index and per-file deflate, loose effects `fx/`); rerun it after a patch. `scripts/upload-costume.mjs` sends the packs to the R2 bucket behind the Asset host (`assets.roc-library.com`, set as the Build variable `NEXT_PUBLIC_ASSET_HOST`; R2 keys are case-sensitive and all lower case, so effects are loaded with `lowercase`), keeping what it sent in gitignored `dev-data/costume/uploaded.json`; setup in `docs/plans/costume-r2-setup.md`. Without the Asset host a push deploys the page with 404 sprites. The browser reads packs with HTTP Range (`src/utils/costumePack.ts`), draws with `spriteComposer.ts`, `costumeCharacter.ts`, `costumeScene.ts` (and STR effects/footprints via `strEffect.ts`, `footprintEffect.ts`); the page is `src/app/costume/CostumeSimulator.tsx`. Effects the game's client draws itself (the table holds only a `hatEffectID`, the code is in the protected exe) are drawn by code to look like the official GIFs, in `src/utils/proceduralEffect.ts` (Electric, Crimson Wave, Blue Aura, Pink Glow and Twinkle are cut from the official GIFs by `scripts/make-effect-sheets.py`; Green Floor is drawn by code to match measurements of its GIF; Shadow is a tinted copy of the character painted behind it (`Scene.shadow`); index entry `key: "proc"`, list `PROCEDURAL_STONES` in the extract script); Shrink is a smaller character (`bodyScale` of the stone, `Scene.bodyScale`). White Body washes the character white (`whiten` on the stone, `Scene.whiten`; `HAT_EF_WHITEBODY` has no file). Roaring is the red C dragon (`efst_c_dragon_red_aura`) painted lilac at load (`tint` on the index entry, `TINTS` in `src/utils/costumeEffects.ts`). They are likenesses, not the game's own code.
- **Item changes**: `public/assets/json/PatchItemChanges.json` (written by `compare_item_ids.py`: item id → `name` + `changes[{field, before[], after[]}]`, colour codes stripped, `{}` when nothing changed) feeds the Change note on `/patch-convert` (`ChangeNote.tsx`, `src/utils/itemChanges.ts`). Description lines are paired with their change by text without colour codes; the file has no line positions, so lines the patch removed are shown at the end of the description.
- **Patch Convert access**: `/patch-convert` opens outside localhost only with `?Key=` equal to `PATCH_CONVERT_KEY` (changed weekly) or `PATCH_CONVERT_MEMBER_KEY` (permanent, for Members), both in the environment; neither set means closed. The dev boards are not opened by either key.
- **Member sign-in** (see GLOSSARY, ADR 0002): Members are Supabase Auth users the owner invites (sign-up is off). The browser talks to Supabase directly (`src/utils/memberAuth.ts`, needs `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` as Build variables); pages are `/member/login`, `/member/forgot`, `/member/set-password` (the link in the Invite and reset emails; add it to Supabase Redirect URLs for `www.roc-library.com` and `localhost:3000`). Usernames live in the Supabase table `members` (`supabase/members.sql`). The Worker route `/api/member` (`src/server/memberHandler.ts`) finds the email for a username and signs in, sends the forgot-password email, and saves a new Member's username; sign-in and forgot are guarded by the Human check (Cloudflare Turnstile, ADR 0003: `src/server/turnstile.ts` verifies before any lookup, widget in `src/components/member/HumanCheck.tsx`; needs `NEXT_PUBLIC_TURNSTILE_SITE_KEY` as a Build variable and `TURNSTILE_SECRET_KEY` as a Worker secret, skipped only outside production when unset); `/api/admin` (`memberAdminHandler.ts`, secret `MEMBER_ADMIN_PASSWORD`) serves the owner's `/admin` page (invite, list, suspend, remove). `PatchGate` opens `/patch-convert` for a signed-in Member before it looks at `?Key=`; an expired session goes to `/member/login?next=/patch-convert&expired=1`. `checkMember` makes no network call of its own (a removed or suspended Member is cut off when the JWT renews). `AccountArea` (in `src/layout/navbar/`) shows the username and sign-out, or an "เข้าสู่ระบบ" link when nobody is signed in, in both the Navbar (`compact`) and the Sidebar head; the Sidebar head also repeats the support link and the Theme mode switch. Emails go out through custom SMTP set in Supabase (Resend).
- Types per feature in `src/types/`.
