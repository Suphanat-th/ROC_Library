# แผน: Costume simulator (`/costume`, ชื่อบนหน้าเว็บ "Simulator Costume ROC")

ศัพท์ตาม `GLOSSARY.md` (Costume simulator, Mount, Hair colour / Body colour) การตัดสินใจเรื่อง sprite อยู่ใน `docs/adr/0004-costume-sprites-on-the-asset-host.md`

สถานะ (26 พ.ย.): Phase 0–4 เสร็จ, Phase 2 (R2) ตั้งและอัปโหลดแล้ว ทดสอบที่ localhost ผ่าน, commit `f64f444` (ยังไม่ push) เหลือ Phase 5 บางข้อ และงานค้างท้ายเอกสาร (รายละเอียดแต่ละรอบอยู่ด้านล่าง)

## ขอบเขต (ตกลงแล้ว)
- **อาชีพ:** Class 1-2, High, Awakened, Extended (ตามรายชื่อใน `src/data/aspdData.ts`) และ Super Novice ทั้งชายและหญิง ไม่รวม 3rd class, Doram, Star Emperor, Soul Reaper และชุดคอสตูม (Summer, Hanbok ฯลฯ)
- **Mount:** Peco Peco (Knight, Lord Knight, Crusader, Paladin, Rebellion), Poring (Novice, Super Novice, Taekwon), Toad (Kagerou, Oboro) หมวกและ Robe ขยับตามจุดยึด (anchor) ในไฟล์ `.act` ของ body ไม่ใส่ตัวเลขชดเชยด้วยมือ
- **สิ่งที่เลือกได้:** อาชีพ, เพศ, ทรงผม, Hair colour, Body colour, สวิตช์ขี่ Mount, headgear ตำแหน่ง Upper / Middle / Lower และ Robe
- **ไม่ทำ:** อาวุธและโล่, สีย้อม headgear (ในเกมไม่มี palette ของ headgear)
- **รายการไอเท็ม:** ใช้ `useItemDb()` เดิม กรองเฉพาะที่มี sprite
- **สิทธิ์เข้าหน้า:** เหมือน Patch Convert คือ Member ที่ล็อกอินแล้ว หรือ `?Key=` ผ่าน `PatchGate`
- **เทคนิค:** วาดในเบราว์เซอร์ด้วย `sprParser.ts` / `actParser.ts` เก็บ sprite บน R2 (Asset host) เป็นไฟล์ก้อนต่อชิ้นต่อเพศ มีสารบัญ อ่านด้วย HTTP Range และเก็บเฉพาะ Robe ที่ผูกกับไอเท็มจริง

## Phase 0: ตรวจข้อมูลก่อนสร้าง (อ่านอย่างเดียว)
- เปิด data.grf (`D:/GAME/RO/GGT-Classic/data.grf`) แบบอ่านอย่างเดียว เพื่อหาว่า:
  - Robe ที่ผูกกับไอเท็มจริงมีกี่แบบ และขนาดรวมเท่าไร
  - จุดยึดใน `.act` ของ body ตอนขี่ Mount เป็นอย่างไร
  - ชื่อไฟล์ body ของ Peco Peco / Poring / Toad แต่ละอาชีพ
  - palette ผม (`data/palette/머리`) และ palette ชุด (`data/palette/몸`) จับคู่กับ sprite อย่างไร
- ตรวจโควตาและราคา R2 ปัจจุบันจากหน้าราคาของ Cloudflare (ตัวเลขใน ADR มาจากความจำ)
- **ผ่านเมื่อ:** รู้ขนาดรวมสุดท้าย และพิสูจน์ได้ว่าหมวกวางถูกตำแหน่งบนตัวที่ขี่ Mount อย่างน้อยหนึ่งอาชีพ

## Phase 1: สคริปต์แตกไฟล์และรูปแบบไฟล์ก้อน
- สร้าง `scripts/extract-costume.mjs` ในแนวเดียวกับ `scripts/extract-navigation.mjs` อ่านจาก data.grf แล้วสร้างไฟล์ก้อนหนึ่งไฟล์ต่อชิ้นต่อเพศ โดยมีสารบัญบอกตำแหน่งของแต่ละอาชีพ
- สร้างไฟล์ JSON ดัชนี (อาชีพ, อาชีพที่ขี่ Mount ได้, ทรงผม, รายการสี, ไอเท็มกับก้อน) ไว้ใน `public/assets/json/`
- เทียบ hash แล้วอัปโหลดขึ้น R2 เฉพาะก้อนที่เปลี่ยน
- **ผ่านเมื่อ:** รันซ้ำแล้วไม่อัปโหลดอะไรเพิ่ม และอ่านอาชีพเดียวจากก้อน Robe ด้วย Range ได้ถูกต้อง

## Phase 2: Asset host บน R2
- สร้าง bucket และโดเมน ตั้งแคชยาว, CORS และ Range โดยใช้ค่า Asset host ที่มีอยู่แล้ว
- ขั้นตอนนี้ต้องใช้บัญชี Cloudflare ของเจ้าของ Claude ทำให้ไม่ได้ จะส่งขั้นตอนให้ลงมือเอง
- **ผ่านเมื่อ:** เบราว์เซอร์โหลดไฟล์ก้อนและอ่านช่วง Range จากโดเมนจริงได้

## Phase 3: ตัวโหลดและตัวแสดงภาพ
- เขียนตัวอ่านไฟล์ก้อน (อ่านสารบัญก่อน แล้วขอเฉพาะช่วงที่ต้องใช้) ต่อเข้ากับ parser เดิม
- ขยาย `src/app/visual/ROViewer.tsx` จากแสดงหนึ่งไอเท็ม เป็นซ้อนหลายชั้น: body, ผม, headgear Lower / Middle / Upper, Robe (อยู่หน้าหรือหลังตามทิศ จาก 8 ทิศ), Mount และสลับ palette สำหรับ Hair colour และ Body colour
- **ผ่านเมื่อ:** อาชีพหนึ่ง ทั้งชายและหญิง วาดได้ครบทุกชั้นทั้งตอนเดินและตอนขี่ Mount โดยไม่มีหมวกลอย

## Phase 4: หน้า `/costume`
- สร้าง `src/app/costume/page.tsx` ครอบด้วย `PatchGate` มีรายชื่ออาชีพที่ค้นหาได้, เพศ, ทรงผม, สี, สวิตช์ Mount (เฉพาะอาชีพที่ขี่ได้) และตัวเลือกไอเท็มแยกตามตำแหน่ง
- เพิ่มลิงก์ใน `src/layout/sidebar/sidebar.tsx` ชื่อ "Simulator Costume ROC" ใช้ token ธีมเพื่อให้ใช้ได้ทั้ง `roc-light` และ `roc-dark`
- **ผ่านเมื่อ:** เปลี่ยนค่าใดๆ แล้วภาพอัปเดตทันที และหน้าพอดีกับจอมือถือ

## Phase 5: เก็บงาน
- `npm run build` และ `npm run lint` ผ่าน (โปรเจกต์ไม่มีสคริปต์ typecheck แยก)
- ดูในเบราว์เซอร์จริง: อย่างน้อยหนึ่งอาชีพต่อกลุ่ม (Class 1-2, High, Awakened, Extended) และทั้ง 3 Mount
- อัปเดตหัวข้อ Architecture ใน `CLAUDE.md` และ `AGENTS.md` ให้ตรงกัน
- **ผ่านเมื่อ:** build ผ่าน ไม่มี error ใน console และ Costume preview ใน Patch Convert ยังทำงานเหมือนเดิม

**ที่ทำให้ต้องแก้แผน**
1. **ฐานรายการไอเท็มไม่พอ (กระทบ Q8):** `useItemDb()` อ่านจาก `PatchItemDB.json` ซึ่งมีแค่ **25 ไอเท็มของ patch** ไม่ใช่ไอเท็มทั้งเกม ดังนั้น Costume simulator ต้องมีรายการไอเท็มใหม่ (ชื่อทรัพยากรมี 11,050 รายการใน data.grf แต่ชื่อที่แสดงยังต้องหาที่มา) ต้องตัดสินใจก่อน Phase 1
2. **ไฟล์ใน data.grf ถูกเข้ารหัส (DES):** body, headgear และ Robe ส่วนใหญ่มี flag เข้ารหัส สคริปต์ `scripts/extract-navigation.mjs` มีตัวถอดรหัสใช้ได้อยู่แล้ว (ผมคัดลอกไปใช้วัดครั้งนี้ ไม่ได้แก้ไฟล์) สคริปต์ใหม่ควรแยกส่วนอ่าน GRF ออกมาใช้ร่วมกัน และต้องเก็บชื่อไฟล์เป็นไบต์ CP949 ไม่ใช้ `toLowerCase()` กับตัวอักษรเกาหลี (จะทำให้ไบต์เพี้ยน)
3. **ขนาด Robe ยังใหญ่:** 3.8 GB ก่อนบีบอัด (ราว 0.7 GB หลังบีบอัด ประเมินจากสัดส่วนรวมของ GRF) อาจต้องตัดแบบที่ใหญ่ผิดปกติหรือรับขนาดนี้

**ยังไม่ได้ทำ**
- ตรวจโควตาและราคา R2 จากหน้า Cloudflare (ยังไม่ได้เปิดดู ตัวเลขใน ADR ยังเป็นความจำ)
- ดูภาพจริงว่าหมวกวางถูกบน Mount (ต้องมีตัวแสดงภาพ จึงเลื่อนไป Phase 3)
- ตรวจจำนวนทรงผมและการจับคู่ palette ผม

### ปิด Phase 0 (อัปเดตหลังคุยกับเจ้าของ)
- **ราคา R2** (ภาพจากหน้าราคาที่เจ้าของส่งมา): Standard storage $0.015/GB-เดือน, Class A $4.50 และ Class B $0.36 ต่อล้านคำขอ, egress ฟรี ไม่มีค่า data retrieval ประมาณ: Robe บีบอัด ~0.7 GB ≈ $0.01/เดือน ทั้งหมดไม่เกิน 5 GB ≈ $0.08/เดือน, 100,000 ครั้งที่เปิดดู × ~30 Range read ≈ $1/เดือน ค่าใช้จ่ายน้อยมากแม้ไม่มี free tier (ส่วน free tier ยังไม่ได้เห็น)
- **ทรงผม:** sprite 42 ทรงต่อเพศ, palette ทรงละ 8–10 สี ครบทุกทรง
- **ตัดสินใจแล้ว:** เก็บ Robe ทั้งหมดก่อน; รายการไอเท็มของ Costume simulator แยกจาก Patch Convert (ไม่ใช้ `useItemDb()` / `PatchItemDB.json`) สร้างจากข้อมูลทั้งเกมใน data.grf
- **ย้ายไปทำที่ Phase 2:** ตรวจ free tier และเพดานไฟล์ของ Workers จากหน้า Cloudflare
- **ย้ายไปทำที่ Phase 3:** ดูภาพหมวกบน Mount (Poring, Peco Rebellion)

### รอบที่ 8 (26 พ.ย.): เอฟเฟกต์แบบสไปรต์, ชื่อโฟลเดอร์ที่ต่างเล็กน้อย, ตัวละครใหญ่ขึ้น
- **เอฟเฟกต์มี 2 แบบ:** `.str` ใน `data/texture/effect/…` และ **สไปรต์ `.spr/.act` ใน `data/sprite/이팩트/<ชื่อ>/`** (21 โฟลเดอร์ เช่น valkyrie_wing, c_jaow_pirun, perm_frost_oblivion, c_aura_of_ghost_s, digital_space) แบบหลังเดิมไม่เคยหา เพิ่มชนิด `effect` ใน `Gear` ของ `spriteComposer.ts` (วาดที่เท้า บนนาฬิกาของตัวเอง หลัง/หน้าตัวละครตามความสูงของภาพแรกใน ACT: สูงกว่า −45 อยู่หน้า) คัดลอกเป็น `fx/<key>/e.spr` + `e.act`
- **โฟลเดอร์ .str ที่ชื่อต่าง:** จับเพิ่มด้วยชื่อไร้เครื่องหมาย (ตัด `efst_`, `c_`) ทั้งชื่อทรัพยากรและชื่อไอเท็ม
- ผล: เอฟเฟกต์แสดงได้ **84 ชิ้น** (.str 74 + สไปรต์ 10) ไม่ได้ 12 ชิ้น (Fluttering Angel's Wing, Moon and Stars, Angel Stairs, Aura of Night/Darkness, Exploding Wave Sca, Floating Stone Of Int, Wonderland Tea Party, Festival Stall, DJ Booth, Hot Spring, Magic Wonderland) ไม่เจอไฟล์เอฟเฟกต์ของมันในข้อมูลเกม ไฟล์เอฟเฟกต์รวม 211 MB
- **/effect ปิดแล้วอะไรหาย:** ในไฟล์เกมมีเพียง `IsEffectHatItem` + ตาราง `effecthatitemtable` (106 ไอเท็ม) ที่เกี่ยวกับ /effect Costume Cons of Poison **ไม่อยู่ในตารางนี้** จึงบอกจากไฟล์ไม่ได้ว่าอะไรหายเมื่อปิด /effect (ส่วนที่เหลือน่าจะฝังใน client) ตอนนี้ปิด /effect = ซ่อนเอฟเฟกต์ (STR, สไปรต์, รอยเท้า, หิน) แต่ไม่ซ่อนภาพของ Costume
- **ตัวละครใหญ่ขึ้น:** canvas 420×440 → 560×580, ขนาดสูงสุด ×2.5 → ×3.5, คอลัมน์ซ้าย 25 → 34 rem

### ช่อง Costume ค้างใต้เวที + หินเอฟเฟกต์ในช่อง Costume (26 พ.ย.)
- แท็บ Costume: ช่องสวมใส่ 4 ช่อง (บน/กลาง/ล่าง/ผ้าคลุม) เป็นแถบเล็กที่ค้างติดใต้เวที (sticky) ไม่เลื่อนหายตอนเลื่อนรายการ เวทีลดเหลือสูง 40% ของจอเฉพาะแท็บนี้ เพื่อให้มีที่ให้รายการ
- หินเอฟเฟกต์: เมื่อใส่ Costume ในช่องใด จะมีกล่อง "หินเอฟเฟกต์ของช่อง…" เหนือรายการ เลือกได้ของช่องนั้น (ป้าย ✦ บนช่องที่มีหิน) ถอด Costume แล้วหินของช่องที่มันครอบถูกถอดด้วย (แท็บเอฟเฟกต์เหลือเฉพาะรอยเท้า)
- หินที่หาเอฟเฟกต์ได้เพิ่มด้วยชื่อโฟลเดอร์ (Water Field → efst_waterfield2) รวม 6 จาก 21
- ช่องหิน (socket) ใต้แต่ละช่อง Costume ในแถบที่ค้างใต้เวที: ปุ่มเส้นประ "◇ หิน" (ว่าง) / "✦ ชื่อหิน" (ใส่แล้ว) ปิดอยู่จนกว่าจะใส่ Costume ในช่องนั้น กดแล้วเปิดหน้าต่างเลือกหินของช่อง (แทนกล่องหินที่เคยอยู่เหนือรายการ)
- ช่อง **ผ้าคลุม (Garment)**: ช่องหินคือ "เอฟเฟกต์เดิน" (รอยเท้า 9 แบบ ซึ่งเกมให้เป็น Enchant ของ Costume Garment) เลือกที่ช่องหินใต้ช่องผ้าคลุม (แสดงเมื่อเลือกท่าเดินและเปิดเอฟเฟกต์) ถอด Costume ผ้าคลุมแล้วรอยเท้าถูกถอดด้วย ย้ายออกจากแท็บเอฟเฟกต์แล้ว
- เอาแท็บเอฟเฟกต์ออก (เหลือ ตัวละคร | Costume | ฉาก/บันทึก) รอยเท้าวาดใหญ่ขึ้น ×1.8 (`FOOTPRINT_SIZE` ใน `footprintEffect.ts`)
- **แก้เอฟเฟกต์ผิด:** รายการในตารางหมวกที่มีแค่ `hatEffectID` (ไม่มีไฟล์) คือเอฟเฟกต์ที่ client วาดเอง เลขนั้นไม่ใช่คีย์ของตาราง (HAT_EF_Electric ชี้ 254 ซึ่งในตารางคือ Kung Fu Panda แต่เกมแสดง Roaring) สคริปต์เลิกตามเลขนี้แล้ว ผล: หิน Electric และ Costume Flaming Blast Wave ที่เคยได้เอฟเฟกต์ผิดตัว ตอนนี้แสดงเป็น "ยังแสดงไม่ได้"

### ออกแบบหน้าใหม่ให้เล่นง่าย (26 พ.ย.): หน้าเดียวเต็มจอ ไม่ต้องเลื่อนทั้งหน้า
- ปัญหา (iPhone SE 375×667): เวทีค้าง + แถบช่อง + ช่องหินกินจอเกือบหมด รายการเหลือไม่ถึงแถว, ปุ่มบนเวทีซ้อนกัน (ท่า "เดิน" ถูกปุ่มทิศบัง), หัวเรื่องกินที่
- หน้าเป็นคอลัมน์สูงเท่าจอ (`100dvh − navbar`): เวที (สูง ~30dvh ในแท็บ Costume / 38dvh แท็บอื่น, ไม่เกินความกว้างจอ) → แถวควบคุม → แถบ 4 ช่อง → แท็บ → แผงตัวเลือก **เลื่อนเฉพาะแผงตัวเลือก** ส่วนบนไม่ต้อง sticky อีกต่อไป
- บนเวทีเหลือแค่ ซูม และ /effect; ท่า (ยืน/นั่ง/เดิน) + หมุนทิศ ◀ ▶ + เริ่มใหม่ (มือถือ) ย้ายเป็นแถวใต้เวที ปุ่มสูง 44px
- ช่องหิน/เอฟเฟกต์เดิน เป็นวงกลมเส้นประเล็กที่มุมของแต่ละช่อง (◇ ว่าง / ✦ ใส่แล้ว) แทนปุ่มกว้างใต้ช่อง
- มือถือซ่อนหัวเรื่อง (เหลือ h1 สำหรับ screen reader) ข้อความแจ้งเตือนย่อเล็ก; ช่องค้นหาของรายการค้างบนสุดของแผง; ไอคอนรายการเล็กลง (5.5rem)
- ยังไม่ได้ดูบนหน้าจอจริง รอภาพจากผู้ใช้
