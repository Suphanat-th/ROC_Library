# Costume simulator sprites live on the Asset host, packed one file per item and gender

The Costume simulator needs every job's body, every headgear and every Robe from the game's data.grf: about 113,600 files and 5.1 GB uncompressed, 90% of it Robes (one file pair per job and gender for each of 183 Robe folders). That cannot go in `public/` (Cloudflare allows 20,000 files per deploy on the free plan, and ADR 0001 already warned that 306 MB of pictures makes builds heavy). So the sprites go to R2 behind the Asset host, which this feature makes real instead of deferred. Files are packed one per item and gender (a Robe's file holds every job) with an index at the start, and the browser reads only the job it needs with HTTP Range, so the file count stays in the low thousands and a player downloads some hundreds of KB per item. Only Robes tied to an item in our item database are packed; unused and duplicated Robe folders are left out. The owner runs the extract script by hand after a patch (like `extract-navigation.mjs`), which uploads only packs whose hash changed. Everything is drawn in the browser with the parsers we already have; no render server.

Considered options:
- Put the files in `public/`: rejected, over the file-count limit and 5 GB in git.
- Run a render server like the reference site's zrenderer: rejected, it costs a server we would host and depends on someone else's if borrowed.
- One R2 object per `.spr`/`.act`: rejected, 113,600 objects and as many requests per view.
- Protect the files (Worker check, signed links, or a private path for unreleased items): rejected by the owner. The R2 files are public, as `public/assets/sprite_data` already is for Patch Convert; only the `/costume` page is gated.

## Consequences

- Anyone who knows a file's address can download it, including sprites of items from a patch not yet released. This is the exposure Patch Convert already has.
- Needs an R2 bucket and a custom domain for the Asset host, an upload step in the owner's routine after each patch, and a check of the free allowance before launch (the pricing page, read 2026-11-26, lists Standard storage $0.015 per GB-month, Class A $4.50 and Class B $0.36 per million requests, egress free; and the R2 sign-up page shows a free monthly allowance of 10 GB storage, 1 million Class A and 10 million Class B operations, $0.00 due now, charged only above those limits, with a card on file). Our packs (5 GB at most, about 0.7 GB for Robes compressed) and first upload (thousands of operations) fit inside it, so the expected cost is $0. Above it, 1 million extra Range reads cost about $0.36.
- The Asset host is `assets.roc-library.com`, set as the Build variable `NEXT_PUBLIC_ASSET_HOST`. It is a different origin from the site and the page sends a `Range` header, so the bucket needs a CORS rule that allows `Range` and exposes `Content-Range`; without it reading a pack fails on production only. A Cache rule on the host (Cache everything, Edge TTL 7 days) keeps most Range reads from becoming R2 Class B operations; after an upload over existing files the owner purges the cache. Tested 2026-11-26 with curl after the first upload: Range reads of a 4 MB pack and of a Robe pack are `MISS` the first time and `HIT` the second, and the CORS preflight (Origin `https://www.roc-library.com`, header `range`) answers 204 (`curl -I`, a HEAD request, always shows `DYNAMIC`, so it is no test of the cache). Steps are in `docs/plans/costume-r2-setup.md`; `scripts/upload-costume.mjs` uploads.
- The packs are gitignored, so a push deploys the page without sprites (every sprite request is a 404) until they are on the host and the Build variable is set. The owner commits and pushes; R2 is set up and tested on localhost first.
- The page stays Members-only for at least two weeks after launch while the R2 usage (Class A/B, storage) is watched against the free allowance; before it opens to everyone, requests are reduced (for example effects are fetched only once /effect is on). The R2 files stay public (see above), so scrapers can spend the allowance once the page is public.
- Members-only closes the page, not the files: `CostumeGate` checks the Member only when the page opens, and anyone who knows a pack's address (visible in the Network tab) can fetch it without signing in; a session that expires while the page is open keeps working until it is closed. The owner accepts this (27 Nov 2026) because the aim is to limit who uses the page and to count its load, not to protect the files. Closing the files would need signed addresses, a large change not wanted now.
- The Costume preview in Patch Convert keeps reading its few sprites from `public/` for now; moving it onto the same packs is a later choice.
- Weapons and shields (about 5,000 files, 111 MB) are left out and can be added later as more packs without changing this layout.
